# Feature Specification: Auth & Login 登录管理系统

**Feature Branch**: `001-auth-login`  
**Created**: 2026-04-07  
**Status**: Draft  
**Input**: User description: 功能：Auth & Login 登录管理系统 (short name: auth-login)；Web 拦截与鉴权、state 防伪造、Custom URI Token 回传、会话刷新与废除、安全与界面约束；非目标见 Assumptions。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 浏览器完成登录并将凭证交回桌面客户端 (Priority: P1)

用户在桌面客户端发起登录后，系统打开默认浏览器进入中控 Web 登录页；用户使用账号密码或第三方（SSO）完成验证。成功后，系统把防伪造校验信息与访问凭证一并交回客户端，使客户端获得用户身份与后续调用中控能力所需的授权上下文。

**Why this priority**: 没有这一条，整个中控平台无法建立可信用户身份，`device-manage`、`skill-center` 等模块缺少统一 User ID 与权限上下文。

**Independent Test**: 仅用「客户端触发 → 浏览器登录 → 客户端收到有效身份凭证」即可端到端验证，不依赖刷新或管理废除能力。

**Acceptance Scenarios**:

1. **Given** 用户已在客户端选择登录且本机已注册约定的深度链接协议，**When** 完成浏览器侧账号密码或 SSO 验证且校验信息匹配，**Then** 客户端在可接受时间内收到与登录会话绑定的访问凭证与续期凭证，并可用于标识该用户。
2. **Given** 登录请求携带了唯一的一次性校验参数，**When** 鉴权成功并回传凭证，**Then** 返回中的校验参数与请求侧一致，客户端可据此拒绝被篡改或重放的响应。
3. **Given** Web 登录页已按约定展示，**When** 用户在常见视口宽度下访问，**Then** 表单与品牌元素居中、布局可用且主要操作可在三步内触达（打开页 → 输入或选择 SSO → 提交）。

---

### User Story 2 - 客户端无感续期与后台会话废除 (Priority: P2)

已登录客户端在访问凭证将过期或已过期时，可通过专用流程用续期凭证换取新的访问凭证，无需再次打开浏览器完整登录。中控后台人员或自动化策略可废除指定会话，使对应凭证立即或短期内失效。

**Why this priority**: 保障日常体验与安全响应能力；在 P1 建立身份后，续期与废除是长期运行与合规运营的必备能力。

**Independent Test**: 在已有有效会话的测试账号上，仅验证「续期成功」与「废除后会话不可用」即可，与浏览器登录页 UI 细节解耦。

**Acceptance Scenarios**:

1. **Given** 客户端持有未废除且仍有效的续期凭证，**When** 调用续期流程，**Then** 获得新的访问凭证（及按需轮换的续期凭证），用户无感于浏览器登录步骤。
2. **Given** 管理员对某登录会话执行废除操作，**When** 客户端随后用旧访问凭证或续期凭证访问受保护能力，**Then** 请求被拒绝或引导重新建立身份。
3. **Given** 废除操作已记录，**When** 审计需要追溯，**Then** 可追溯「谁、何时、对哪类会话」执行了废除（粒度在规格层面为会话/用户级，具体字段在计划中细化）。

---

### User Story 3 - 登录成功过渡与唤醒失败时的兜底 (Priority: P2)

鉴权成功后，用户看到一个简短过渡界面（例如提示正在返回客户端）。若操作系统未能按约定唤醒客户端，用户可复制凭证文本或一键重试唤醒，仍能完成登录闭环。

**Why this priority**: 深度链接在部分环境不可靠；无兜底将导致大量失败工单，抵消瘦客户端登录策略的收益。

**Independent Test**: 在禁用或拦截深度链接的测试环境中，仅验证复制/重试路径即可，不依赖真实 SSO 厂商。

**Acceptance Scenarios**:

1. **Given** 浏览器侧鉴权已成功，**When** 页面加载过渡态，**Then** 用户看到明确成功提示与「正在返回客户端」类文案。
2. **Given** 深度链接未触发客户端，**When** 用户使用页面提供的复制或重试入口，**Then** 仍能获得与成功鉴权一致的凭证信息或重新触发唤醒流程。

---

### Edge Cases

- 校验参数缺失、重复或与会话存储不一致时，拒绝发放凭证并给出可理解错误，不泄露内部实现细节。
- 第三方登录取消、超时或 IdP 错误时，用户可安全返回或重试，不产生半状态会话。
- 续期凭证泄露或被盗用的尝试：通过短寿命访问凭证、废除与会话绑定策略降低风险（具体上限在计划中量化）。
- 同一用户多设备、多会话并存时，废除仅影响目标会话，不误伤其他设备（除非产品明确「全端下线」——默认单会话废除）。
- 客户端未安装或未注册深度链接协议时，过渡页必须可走复制或人工导入路径，而非静默失败。

## Requirements *(mandatory)*

### Functional Requirements

**Web 与客户端协同**

- **FR-001**: System MUST 支持由桌面客户端发起、在系统默认浏览器中打开中控 Web 登录入口的登录流程；客户端 MUST NOT 在本功能范围内要求内置原生账号密码表单（瘦客户端策略）。
- **FR-002**: System MUST 为每次登录请求生成并跟踪唯一校验参数（`state`）；鉴权成功回传时 MUST 携带同一校验参数，供客户端与中控侧比对，以防范跨站请求伪造类攻击。
- **FR-003**: System MUST 在鉴权成功后，通过双方约定的深度链接（Custom URI Scheme）将访问凭证与续期凭证传回客户端；协议名 MUST 在客户端安装时由安装包注册至操作系统。
- **FR-004**: System MUST 提供续期能力，使持有有效续期凭证的客户端可换取新的访问凭证而无需重新走完整浏览器登录（路径在实现阶段命名为 `/refresh` 或等价，以合同为准）。
- **FR-005**: System MUST 提供管理侧能力，使授权角色可废除指定登录会话或等价令牌链，使后续请求失败直至重新登录。

**安全与平台约束**

- **FR-006**: System MUST 将账户密码以强 salted hashing 存储（允许算法族包括 bcrypt、Argon2 等当前公认强算法），严禁明文或可逆形式存放密码。
- **FR-007**: System MUST 将「访问凭证与续期凭证的签发与校验」集中在单一平台 enforcement 层（例如 API 网关或独立鉴权中间件），业务服务 MUST NOT 各自重复实现不一致的校验逻辑。

**界面与体验**

- **FR-008**: Web 登录页 MUST 提供极简布局：品牌标识、账号、密码、第三方登录入口；主要视觉区域居中，适配常见桌面与移动浏览器宽度。
- **FR-009**: 登录成功后的过渡页 MUST 提供成功反馈文案，并在深度链接失败时提供复制凭证与/或重试唤醒的明确入口。

**平台集成**

- **FR-010**: System MUST 向 `device-manage`、`skill-center` 等上游消费方暴露稳定用户标识与权限上下文契约（具体字段与命名在合同与计划中定义），本功能为其身份底座。

### Key Entities *(include if feature involves data)*

- **User（用户账户）**: 登录主体；含账户标识、凭据存储引用、与管理员/角色关系（细粒度授权可后续扩展）。
- **Login Session（登录会话）**: 浏览器或客户端侧一次登录实例；可与设备、IP、创建时间绑定，用于废除与审计。
- **Token Pair（访问与续期凭证对）**: 短期访问凭证与长期续期凭证的配对；与会话及用户绑定，可轮换。
- **Authorization State Record（授权状态/State）**: 与单次登录请求绑定的随机状态，用于回传校验与防重放。

- [x] **固定技术栈**：本规格不绑定实现语言；实现阶段 MUST 采用宪章规定的 Python/FastAPI 与 React 技术栈（见计划与仓库宪章）。
- [x] **子路径部署**：Web 登录页、回调与 API MUST 服从统一 Base Path；具体 `basename`、路由前缀、Cookie Path 与代理规则在 `plan.md` 与合同中与宪章对齐。
- [x] **双轨认证**：浏览器侧使用会话或等价 Web 登录态完成身份建立；客户端与后续 API 使用 Bearer 式访问凭证调用；二者边界在本规格与 FR 中已区分。
- [x] **契约优先**：对外路径、方法、凭证形状、错误语义及 Legacy 策略 MUST 在规格后续合同（`/specs/001-auth-login/contracts/`）中落地；本 spec 为需求来源。

- [x] **安全与运维**：HTTPS、密钥隔离、管理废除操作鉴权、认证与废除相关日志要求在 FR 与成功标准中已体现；生产禁用不安全调试开关在计划中对接宪章。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在实验室网络条件下，90% 的首次登录尝试（含账号密码与一次 SSO 模拟）从客户端点击登录到客户端获得可用访问凭证，在 3 分钟内完成。
- **SC-002**: 在续期凭证仍有效的前提下，95% 的续期请求在 5 秒内返回新的访问凭证且用户无需感知浏览器跳转。
- **SC-003**: 会话被废除后，99% 的后续受保护请求在 30 秒内被拒绝或要求重新建立身份（以可观测的业务错误码或等价用户可见状态衡量）。
- **SC-004**: 在深度链接被故意禁用的测试中，100% 的受试用户可通过过渡页复制或重试在 5 分钟内完成凭证回收（培训除外）。

## Assumptions

- 中控平台已有或可同期交付关系型数据库，用于用户与会话持久化；本规格不规定表结构细节。
- 第三方 SSO 的具体厂商与协议在集成阶段选定；规格层要求「可插拔、可回退到本地账号密码」。
- 客户端安装包负责注册约定的深度链接协议；中控只负责生成合法回调 URL 与过渡页兜底。
- **非目标（明确排除）**：客户端内嵌原生登录表单；复杂用户画像、积分或社交关系模块；本规格之外的模块业务规则。
