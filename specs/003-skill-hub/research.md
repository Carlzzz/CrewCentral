# Research: 003-skill-hub

**Date**: 2026-04-07

## 1. 技能绑定配置的数据存储

**Decision**: 绑定配置采用结构化 JSON 文档列存储，并提供按关键路径筛选能力。  

**Rationale**: 配置字段随技能类型演进，固定列模型会频繁迁移；结构化 JSON 便于扩展与灰度发布。  

**Alternatives considered**:
- 纯文本存储：查询与校验成本高，不满足“灵活查询”约束。  
- EAV 拆表：模型复杂且联表开销大，不利于快速迭代。  

## 2. 技能包下载防盗链

**Decision**: 使用短效下载凭据（签名 token）换取真实下载地址，凭据绑定技能版本、主体、过期时间。  

**Rationale**: 能阻断长期外泄链接复用，同时保持客户端下载流程稳定。  

**Alternatives considered**:
- 固定公开 URL：无法满足防盗链要求。  
- 仅 Referer 校验：客户端场景不可靠，且易被绕过。  

## 3. 客户端热更新流程

**Decision**: 客户端拉取分发清单后，仅当 `target_version` 高于本地版本才触发下载；下载后必须比对服务端下发 hash，失败则回退旧版本并上报。  

**Rationale**: 可避免不必要下载，且把完整性校验前置为加载门禁。  

**Alternatives considered**:
- 每次都下载最新包：网络与存储浪费大。  
- 仅依赖传输层校验：不能覆盖落盘后文件损坏。  

## 4. 授权冲突处理（用户 vs 用户组）

**Decision**: 采用确定性优先级：用户级绑定优先于用户组绑定；同层冲突按最新生效时间覆盖。  

**Rationale**: 行为可解释、易回放，避免同一用户拿到不一致参数。  

**Alternatives considered**:
- 多策略合并：规则过于复杂，运营难以预期。  
- 随机或首条命中：不可预测，不可审计。  

## 5. 技能大厅页面布局策略

**Decision**: 采用“左侧分类导航 + 右侧卡片流网格”主布局；卡片包含图标、名称、版本、描述、分发开关、配置入口，并在悬浮态显示“查看文档/部署”快捷操作。  

**Rationale**: 与“应用商店/插件市场”认知一致，便于后续新增分类与卡片操作。  

**Alternatives considered**:
- 纯表格：不利于快速浏览与视觉扩展。  
- 单列详情流：批量操作效率低。  

## 6. 与既有模块的边界

**Decision**: `skill-hub` 复用 `auth-login` 认证身份；设备平台过滤条件复用 `device-manage` 上报属性，不在本模块重建设备主数据。  

**Rationale**: 保持单一职责，降低跨域重复建模。  

**Alternatives considered**:
- 在 skill-hub 新建用户/设备镜像表：数据一致性与维护成本过高。
